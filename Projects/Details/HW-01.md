## Project Objective

Create a practical, interactive **sensor calibration notebook** using the existing FPGA multiply–accumulate (MAC) accelerator. A raw sensor value `B` is transformed using `Y = A × B + C`, where `A` is a user-adjustable gain and `C` is an offset. The notebook should show how different calibration settings change the measurement curve, compare FPGA and Python outputs and explain transfer overhead.

This project **must go beyond** repeating the original Lab06 MAC and performance notebooks.

Use the existing paired `lab06.bit` and `lab06.hwh`. The single-operation MAC computes **unsigned** `A×B+C`, with 8-bit `A`, 8-bit `B`, 16-bit `C` and 32-bit `Y`. It does **not** support signed arithmetic or a vector input in one call. Repeated sample processing is orchestrated by Python, with an AXI register transaction for each MAC.

## Practical Assignment

1. **Sensor sample dataset.** Generate a 256-sample test series with values in `0…255` (for example, a slowly varying measurement plus small noise), or obtain a real sensor series and explicitly map it into the supported unsigned 8-bit input range.
2. **Interactive calibration.** Add two notebook controls: gain `A` (integer `0…255`) and offset `C` (integer `0…65535`). For each sample `B`, call the FPGA MAC and read the result. Changes to the controls must trigger a recalculation without reloading the overlay.
3. **Visual comparison.** Plot raw samples, FPGA-calibrated samples and a Python reference. Use clear axis labels and state that raw and calibrated values may have different numeric ranges.
4. **Correctness tests.** Check all 256 FPGA values against Python; report mismatches. Include at least three calibration settings and boundary cases such as zero gain and the maximum expected output.
5. **Performance experiment.** Measure the time for processing the entire dataset through single-operation FPGA MAC calls, a regular Python loop and a NumPy vectorized expression. Repeat measurements and show a comparison table or chart.
6. **Interpretation.** Explain why the existing FPGA overlay may lose to NumPy for this task due to repeated Python/MMIO transactions. Do not claim that the `lab06_batch` overlay can process arbitrary input arrays: it generates its own internal operands.

## Expected Live Demonstration

The examiner changes `A` and `C` in the Jupyter interface. The notebook then reads actual FPGA results for the dataset, updates the calibration plot, confirms numerical correctness and displays the three measured execution times.
